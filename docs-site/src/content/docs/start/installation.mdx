With the released dependency lockfile, the core, ONNX Runtime, and Tract builds support Rust 1.92
or newer. On AArch64 targets with `fp16`, including Apple Silicon macOS, enabling `candle` requires
Rust 1.94 or newer. See [Rust version requirements](/reference/feature-flags/#rust-version-requirements)
for the backend and dependency-resolution details.

<Tabs>
  <TabItem label="CLI">

    ```sh
    cargo install sceptre-cli --locked
    ```

    `--locked` uses the dependency versions tested for that release.

    The CLI's default feature set is `["ort-bundled", "download"]`, so this produces a
    self-contained binary: a prebuilt ONNX Runtime is fetched and linked at build time, and models
    download and cache at first use. No `ORT_DYLIB_PATH`, no separately installed
    `libonnxruntime`.

    [Prebuilt release archives](https://github.com/xberg-io/sceptre/releases/latest) support Linux
    x86_64/ARM64, macOS ARM64, and Windows x86_64. They include MCP support, bundled ONNX Runtime,
    and model downloads. Extract the archive and put `sceptre` (`sceptre.exe` on Windows) on `PATH`.

    When installing from Cargo, add the `mcp` feature to expose the MCP server subcommand:

    ```sh
    cargo install sceptre-cli --locked --features mcp
    ```

    **Targets with no prebuilt ONNX Runtime.**
    `ort` publishes prebuilt runtimes for a fixed target list. These have none, and the default
    install fails **at build time** with ort-sys's own
    `no prebuilt binaries available for target ...`:

    - `x86_64-apple-darwin` (Intel macOS)
    - every `*-unknown-linux-musl` target (Alpine)
    - `armv7-unknown-linux-gnueabihf`
    - `riscv64gc-*`
    - `*-unknown-freebsd`
    - `i686-*`, `s390x-*`, `powerpc64le-*`

    Either bring your own `libonnxruntime`:

    ```sh
    cargo install sceptre-cli --locked --features ort-dynamic
    ```

    or build the pure-Rust backend and select it at runtime:

    ```sh
    cargo install sceptre-cli --locked --no-default-features --features tract,download
    sceptre run receipt.png --backend tract
    ```

    <Aside type="note">
      Cargo features are additive, so `--features ort-dynamic` unions with the default rather than
      replacing it — and it still wins: `load-dynamic` implies `ort-sys/disable-linking`, which the
      ort-sys build script checks before its prebuilt-download branch. Switching ONNX Runtime
      provisioning therefore never needs `--no-default-features`. Only the `tract` path does,
      because it has to drop `ort` from the dependency graph entirely.
    </Aside>

  </TabItem>
  <TabItem label="Library">

    The library ships `default = []` — no backend and no download support are enabled by default.
    Enable a backend feature and, typically, `download`:

    ```toml
    [dependencies]
    sceptre = { version = "0.8", features = ["ort-bundled", "download"] }
    ```

    See [Feature flags](/reference/feature-flags/) for every flag and when to pick it, and
    [Backends](/concepts/backends/) for the `ort` vs. `tract` tradeoff.

  </TabItem>
  <TabItem label="MCP server">

    The MCP surface is behind the `mcp` cargo feature, exposed as the `sceptre mcp` subcommand.
    Release archives include MCP support. For a Cargo install, enable `mcp` (see the CLI tab),
    or depend on the library with `mcp` plus a
    backend and `download`:

    ```toml
    [dependencies]
    sceptre = { version = "0.8", features = ["ort-bundled", "download", "mcp"] }
    ```

  </TabItem>
</Tabs>

## Model download and caching

The CRAFT detector and the gen2 recognizers are first-party ONNX artifacts fetched from Hugging Face
(`xberg-io/sceptre-*`) on first use. Each download is verified against a pinned SHA-256 before use.

Models are cached in the standard Hugging Face hub cache — `HF_HUB_CACHE` → `HUGGINGFACE_HUB_CACHE`
→ `$HF_HOME/hub` → `~/.cache/huggingface/hub` — so the library, the CLI, and any other Hugging Face
tooling on the machine share one cache store. Every run after the first reads the cached models with
no network access.

Verification happens **as bytes download**. A cache hit is not re-hashed: the cached artifact is
checked for being a readable, non-empty regular file and then used directly. A hash mismatch found
on a download evicts the artifact and its backing blob, so a corrupt entry self-heals on the next
run rather than being served forever.

<Aside type="tip">
  Run `sceptre models download --all` (see [CLI guide](/guides/cli/)) to prefetch every model ahead
  of time — useful for building an offline image or warming a CI cache. See
  [Offline and CI](/guides/offline-and-ci/) for the full recipe.
</Aside>
